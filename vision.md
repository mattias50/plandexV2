# Plandex Analysis for Manualen.nu

## Architecture Overview

Plandex consists of three main components:

1. **CLI (`app/cli/`)**: Command-line interface for user interaction
2. **Server (`app/server/`)**: Backend service with API endpoints
3. **Shared (`app/shared/`)**: Common code, data models, and settings used by both

## Key Features Relevant to Manualen.nu

### 1. Plans System (Perfect for Book Metaphor)
- **Hierarchical Structure**: Plans can have subplans (chapters can have sections)
- **Content Management**: Plans store content generated by AI (book pages)
- **Versioning**: Branching system for different versions of plans (book editions)
- File in `app/shared/plan_settings.go` defines plan status and settings

### 2. AI Integration Architecture
- **Multiple Providers**: Support for OpenAI, Together, OpenRouter (we'll add Anthropic and Google)
- **Role-Based System**: Different AI roles for different tasks (planner, builder, etc.)
- **Model Settings**: Temperature, top_p, context handling all configurable
- **System Messages**: Each role has its own system message/prompt

### 3. Web Capabilities
- **Routes & Handlers**: `app/server/routes.go` and `app/server/handlers/` 
- **API Endpoints**: Already has HTTP endpoints for plans, contexts, conversations
- **URL Handling**: `app/cli/url/url.go` provides URL functionality (need to explore further)

### 4. Database Integration
- **PostgreSQL**: Used for persistence of plans, contexts, conversations
- **Migrations**: Structured approach to database schema evolution
- **Helpers**: Database helpers for various entities (`app/server/db/`)

### 5. UI Components (Terminal-focused)
- **TUI**: Terminal UI for changes (`app/cli/changes_tui/`)
- **Stream TUI**: For monitoring streaming responses (`app/cli/stream_tui/`)
- *Note: No web UI components directly visible*

## Core Components for our Book Mirror

### Plans as Book Structure
- Plans = Chapters
- Subplans = Sections
- Content = Page content
- File: `app/shared/data_models.go` contains the Plan structure

```go
type Plan struct {
    Id              string     `json:"id"`
    OwnerId         string     `json:"ownerId"`
    ProjectId       string     `json:"projectId"`
    Name            string     `json:"name"`
    SharedWithOrgAt *time.Time `json:"sharedWithOrgAt,omitempty"`
    TotalReplies    int        `json:"totalReplies"`
    ActiveBranches  int        `json:"activeBranches"`
    ArchivedAt      *time.Time `json:"archivedAt,omitempty"`
    CreatedAt       time.Time  `json:"createdAt"`
    UpdatedAt       time.Time  `json:"updatedAt"`
}
```

- File: `app/cli/lib/context_*.go` files manage input context

## Conclusion

Plandex provides an excellent foundation for Manualen.nu, especially its Plans system and AI integration architecture. The book interface can be built as a mirror of the Plans structure, with Ghost AI added as a core role to guide users.

The biggest development effort will be the web UI layer that transforms the Plans concept into a visual book interface, but the underlying data structure and AI capabilities align perfectly with our vision.

Key insights from the analysis:

Perfect Structure Alignment: Plandex's Plans system maps naturally to a book metaphor (Plans = Chapters, Subplans = Sections)
AI Integration Architecture: The existing role-based system is ready for extending with Ghost AI
Web Capabilities: Plandex has HTTP routes and handlers we can build upon
Database Integration: PostgreSQL backend can store all our book content and structure
Implementation Strategy: Clear path for adding Ghost AI and building the book interface

Manualen.nu Project PlanManualen.nu Project Plan
Core Concept
Manualen.nu is a platform where the digital book interface directly mirrors the Plandex Plans system. This fundamental concept is the cornerstone of the entire platform:

Book = Plans System: The digital book UI is a 1:1 visual representation of the underlying Plandex Plans hierarchy
Chapters = Top-level Plans: Each chapter in the book corresponds to a Plan in Plandex
Sections = Subplans: Book sections represent Subplans in Plandex
Content = Plan content: The content displayed in the book is generated by Plandex's AI roles

Ghost AI Role
Ghost AI is a core role within Plandex that serves as the user's guide to navigating and understanding the Plans system through the book interface:

Implemented with Gemini 2.0 Pro: Uses Google's multimodal LLM for visual, audio, and text understanding
Appears as a friendly guide: Always present but unobtrusive in the UI
Multimodal capabilities: Can analyze screenshots, process voice, and provide contextual guidance
Context-aware: Understands where the user is in the Plans hierarchy and what they're looking at

Mixed Provider Model Configuration
Manualen.nu uses a mixed provider model configuration in Plandex:
CopyModels:
- Core roles (planner, builder, etc.): Claude 3.7 Sonnet (Anthropic)
- Ghost role: Gemini 2.0 Pro (Google)
- Support roles (names, commit-messages): GPT-3.5 Turbo (OpenAI)
